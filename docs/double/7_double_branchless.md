Все константы здесь выведены из двух чисел: 76 (во сколько бит нормализуем W) и 54 (какая длина W у нас самая короткая).

## Что нужно получить

Для округления нужно привести W к 76-битному W′ ∈ [2^75; 2^76) (так частное `q = W′/5^9` получает 55–56 бит, а старшая половина `h` умещается в 12 бит). Пусть `b` — длина W в битах, тогда

```
sh = b − 76,     W′ = W >> sh   (при sh < 0 это сдвиг влево)
```

В старой версии было `if (sh > 0) { сдвиг вправо } else { сдвиг влево }` — ветка по длине числа, и она непредсказуема на смешанных данных. Теперь любое направление собирается из двух сдвигов с неотрицательными счётчиками: сначала всегда влево на константу L, потом всегда вправо на `t = sh + L`.

## Откуда 22

Правый сдвиг на `t` должен быть неотрицательным для любого W, который сюда попадает. Туда попадает `W ≥ 2^53` (всё меньше уходит в Clinger-путь), то есть `b ≥ 54`: у `2^53` ровно 54 бита. Наименьший `sh` получается при `b = 54`:

```
sh_min = 54 − 76 = −22   ⇒   L ≥ 22
```

Значит, 22 — наименьшее подходящее L. Верхняя граница: W < 2^93, и `W << L` должно умещаться в 128 бит: `93 + L ≤ 128`, то есть L ≤ 35. Любое L от 22 до 35 даёт верный результат, а 22 просто минимальное: `h0` получается не длиннее 51 бита, `t` лежит в `[0; 39]`. Если когда-нибудь поменяете порог Clinger, пересчитайте константу как `L = 76 − (минимальная длина W)`: для порога `2^52` было бы 23.

## Как работает код по шагам

**1. Сдвиг влево на 22, 128-битный (`h0:l0 = W << 22`):**

```java
long h0 = (hi << 22) | (lo >>> 42);    // 42 = 64 − 22, биты lo, перешедшие в старшее слово
long l0 = lo << 22;
```

Потерь нет: `W << 22 < 2^115`. Младшие 22 бита `l0` — нули.

**2. Сдвиг вправо на `t = sh + 22 ∈ [0; 39]`:**

```java
long h = h0 >>> t;
long l = (l0 >>> t) | ((h0 << 1) << (63 - t));
```

Для `l` нужно `(l0 >>> t) | (h0 << (64 − t))`. Но в Java счётчик сдвига берётся по модулю 64, и при `t = 0` выражение `h0 << 64` превратилось бы в `h0 << 0`, то есть ошибочно подмешало бы `h0`. Поэтому сдвиг разбит на два: `(h0 << 1) << (63 − t)`. При `t ≥ 1` это то же самое, что `h0 << (64 − t)`, а при `t = 0` младший бит `h0 << 1` равен нулю, и результат нулевой, как и надо.

**3. Потерянные биты (sticky):**

```java
long lost = l0 & ((1L << t) - 1);      // младшие t бит l0, которые «упали» при сдвиге вправо
```

При сдвиге вправо меньше чем на 64 теряются только младшие `t` бит `l0`. Из них 22 младших — нули, добавленные на шаге 1, они на результат не влияют. Остаются `t − 22 = sh` младших бит самого W, ровно те, что отбросил бы прямой сдвиг `W >> sh`. Если `t ≤ 22` (то есть `sh ≤ 0`, левый сдвиг), `lost = 0`. Дальше `lost | r` (где `r` — остаток от деления на 5^9) даёт признак «справа было что-то ненулевое».

**4. Откуда `sh`:**

```java
int nlz = nlzHi + (-(nlzHi >>> 6) & Long.numberOfLeadingZeros(lo));
int sh = (128 - nlz) - NORM_BITS_D;    // b − 76
```

`nlz` — число ведущих нулей 128-битного W. Если `hi ≠ 0`, то `nlzHi < 64`, `nlzHi >>> 6 = 0`, маска нулевая, и `nlz = nlzHi`. Если `hi = 0`, то `nlzHi = 64`, `nlzHi >>> 6 = 1`, маска из единиц, и `nlz = 64 + nlz(lo)`. Тернарий C2 превращал в ветку, арифметика не может.

## Три примера

| длина W, `b` | `sh` | `t` | что получается |
|---|---|---|---|
| 54 | −22 | 0 | `W << 22` целиком, правого сдвига нет, `lost = 0` |
| 76 | 0 | 22 | `(W << 22) >> 22 = W`, `lost` — 22 нулевых бита |
| 93 | 17 | 39 | `(W << 22) >> 39 = W >> 17`, `lost` — 22 нуля плюс 17 младших бит W |

Во всех трёх случаях результат лежит в `[2^75; 2^76)`, `h < 2^12`, и дальше идёт общее деление двумя шагами по 32 бита и округление.

Проверка: метод сверен с `BigDecimal.doubleValue()` на 3,07 млн значений (для W от `2^53` до `2^93`, включая границы `2^b ± 2`, ничьи и переносы при `m = 2^53`), расхождений нет.
