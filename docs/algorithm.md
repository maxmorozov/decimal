Ниже вывод всех констант, а затем код с готовыми комментариями. Все числа проверены на границах (минимальное и максимальное W), а сам код я не запускал.

## Базовая формула

`value = W · 10^-9`, где `10^9 = 2^9 · 5^9`. Поэтому

```
value = W / (5^9 · 2^9) = (W / D) · 2^-9,   D = 5^9 = 1 953 125
```

- Деление на степень двойки ничего не стоит и сводится к показателю экспоненты. Отсюда константа `-9`.
- Настоящее деление остаётся только на `D`, и оно целочисленное.
- `2^20 = 1 048 576 < D < 2^21 = 2 097 152`, то есть `log2(D) ≈ 20,898`. От этого неравенства зависят все оценки ниже.

## Почему 76

Нормализованное `W'` лежит в `[2^75; 2^76)`. Тогда

- нижняя граница: `q ≥ 2^75 / D = 2^75 / 2^20,898 ≈ 2^54,1`, то есть `q ≥ 2^54`, минимум 55 бит;
- верхняя граница: `q < 2^76 / D ≈ 2^55,1 < 2^56`, то есть максимум 56 бит.

Итого `len(q) ∈ {55, 56}`, и `drop` принимает только два значения. Если взять 75 бит, нижняя граница станет `2^53,1`, а `q` может быть 54-битным, и формула `drop` перестаёт быть двузначной. Поэтому 76 — минимальное значение, дающее инвариант `len(q) ∈ {55, 56}`. Брать больше можно, но это даёт лишь длинные `q` без выгоды. Предел сверху ограничен тем, что `q` и первый делимый должны оставаться положительными `long`.

## Почему деление идёт двумя шагами по 32 бита

`W' = h·2^64 + l`. Делим в системе по основанию `2^32`:

```
cur1 = h·2^32 + (l >>> 32)        < 2^12 · 2^32 = 2^44         (влезает)
q1   = cur1 / D                   < 2^44 / 2^20 = 2^24
r1   = cur1 mod D                 < D < 2^21
cur2 = r1·2^32 + (l & 0xFFFFFFFF) < D · 2^32 < 2^53            (влезает)
q0   = cur2 / D                   < 2^32                       (так как r1 < D)
r    = cur2 mod D
q    = q1·2^32 + q0               < 2^24 · 2^32 = 2^56
```

Условие `q0 < 2^32` следует из `r1 < D`, и без него `q1 << 32 | q0` было бы неверным. Остаток `r` последнего шага и есть остаток всего деления `W' mod D`.

## Сдвиги по sh

- `sh > 0` (W длиннее 76 бит). Сдвигаем вправо. Потерянные биты берутся из `lo`, так как `sh ≤ 17 < 64`. Это `sticky = lo & ((1L << sh) − 1) != 0`. Строка `l = (lo >>> sh) | (hi << (64 − sh))` безопасна, так как `64 − sh ∈ [47; 63]`.
- `sh ≤ 0`, `k = −sh ∈ [0; 11]` (W короче 76 бит). Сдвигаем влево, потерь нет. Выражение `lo >>> (64 − k)` в Java при `k = 0` равно `lo >>> 0 = lo`, а не 0. Поэтому используется `(lo >>> 1) >>> (63 − k)`: при `k = 0` это `>>> 63` от значения с нулевым старшим битом, то есть 0, а при `k ≥ 1` оно равно `lo >>> (64 − k)`.
- После сдвига `h = hi << k | …` имеет `(bits − 64) + (76 − bits) = 12` бит, откуда `h < 2^12`.

## Экспонента: p и смещение 1074 / 149

Итоговое равенство: `W' = floor(W / 2^sh)`, поэтому `value = (q + дробь) · 2^(sh−9)`. После отбрасывания `drop` бит получаем `value ≈ m · 2^p`, где

```
p = drop + sh − 9
```

Для double при `m ∈ [2^52; 2^53)` значение равно `1,f · 2^(52+p)`, то есть смещённая экспонента `E = 52 + p + 1023 = p + 1075`. Биты числа: `E << 52 | (m − 2^52)`. Заменяем `− 2^52` на уменьшение поля экспоненты на единицу и получаем

```
bits = ((p + 1075) << 52) + m − (1L << 52) = ((p + 1074) << 52) + m
```

Для float: `m ∈ [2^23; 2^24)`, `E = 23 + p + 127 = p + 150`, `bits = ((p + 149) << 23) + m`.

Перенос при округлении (`m` стало `2^53`) обрабатывается автоматически: сложение даёт `((p + 1076) << 52)`, то есть экспонента выросла на 1, а мантисса стала нулём. Это именно `2^(p+53)`.

Проверка диапазонов (субнормалов и переполнения нет):
- double: `p ∈ [2 − 11 − 9; 3 + 17 − 9] = [−18; 11]`, поле экспоненты `p + 1075` далеко от 0 и от 2047;
- float: `p ∈ [31 − 11 − 9; 32 + 17 − 9] = [11; 40]`, поле `p + 150 ≤ 190 < 255`.

## Код с комментариями

```java
// 10^9 = 2^9 * 5^9  =>  W * 10^-9 = (W / 5^9) * 2^-9
private static final long D5_9 = 1_953_125L;          // 5^9;  2^20 < D5_9 < 2^21 (log2 ≈ 20.898)
private static final int NORM_BITS = 76;              // |W'| = 76 бит  =>  q = W'/D имеет 55 или 56 бит
private static final int EXP_SHIFT = 9;               // множитель 2^-9

/** (hi:lo) * 10^-9 -> double, hi != 0 (W от 2^64 до 2^93), round-half-even. */
public static double toDoubleNanosHi(long hi, long lo) {
    // W имеет bits = 65..93 бит; sh = bits - 76 лежит в [-11; 17]
    int sh = (128 - Long.numberOfLeadingZeros(hi)) - NORM_BITS;

    // Приводим W к W' ∈ [2^75; 2^76) в виде (h:l); h < 2^12
    long h, l;
    boolean sticky;
    if (sh > 0) {                                      // сдвиг вправо, 1..17: теряем младшие биты lo
        sticky = (lo & ((1L << sh) - 1)) != 0;
        l = (lo >>> sh) | (hi << (64 - sh));           // 64 - sh ∈ [47; 63]
        h = hi >>> sh;
    } else {                                           // сдвиг влево на k = 0..11, потерь нет
        int k = -sh;
        h = (hi << k) | ((lo >>> 1) >>> (63 - k));     // = lo >>> (64 - k), но корректно и при k == 0
        l = lo << k;
        sticky = false;
    }

    // q = floor(W' / D), r = W' mod D; деление в системе по основанию 2^32
    long cur = (h << 32) | (l >>> 32);                 // < 2^44
    long q1 = cur / D5_9;                              // < 2^24
    long r = cur - q1 * D5_9;                          // < D < 2^21
    cur = (r << 32) | (l & 0xFFFFFFFFL);               // < D * 2^32 < 2^53
    long q0 = cur / D5_9;                              // < 2^32, так как r < D
    r = cur - q0 * D5_9;
    long q = (q1 << 32) | q0;                          // [2^54; 2^56): 55 или 56 бит
    sticky |= r != 0;

    // 53 бита мантиссы: drop = len(q) - 53 = 2 или 3  (q >>> 55 == 1 <=> len == 56)
    int drop = 2 + (int) (q >>> 55);
    long m = q >>> drop;
    long rem = q & ((1L << drop) - 1);
    long half = 1L << (drop - 1);
    if (rem > half || (rem == half && (sticky || (m & 1) != 0))) m++;

    // value ≈ m * 2^p, m ∈ [2^52; 2^53]
    int p = drop + sh - EXP_SHIFT;
    // E = p + 1075; биты = (E << 52) | (m - 2^52) = ((p + 1074) << 52) + m
    // m == 2^53 (перенос) даёт экспоненту +1 и нулевую мантиссу, то есть верный результат
    return Double.longBitsToDouble(((long) (p + 1074) << 52) + m);
}
```

Для float отличаются только три строки:

```java
int drop = 31 + (int) (q >>> 55);                      // len(q) - 24 = 31 или 32
...
int p = drop + sh - EXP_SHIFT;                         // m ∈ [2^23; 2^24]
return Float.intBitsToFloat((int) (((long) (p + 149) << 23) + m));   // E = p + 150
```

## Что стоит добавить в тест

Инварианты, на которых всё держится, можно проверять в коде напрямую. Это даёт ранний сигнал, если кто-то изменит константы:

```java
@Test
void normalizationInvariants() {
    BigInteger d = BigInteger.valueOf(1_953_125L);
    BigInteger wMin = BigInteger.ONE.shiftLeft(75);            // W' минимальное
    BigInteger wMax = BigInteger.ONE.shiftLeft(76).subtract(BigInteger.ONE);
    assertEquals(55, wMin.divide(d).bitLength());
    assertEquals(56, wMax.divide(d).bitLength());
    // intermediate
    assertTrue(BigInteger.ONE.shiftLeft(44).bitLength() <= 63);
    assertTrue(d.shiftLeft(32).bitLength() <= 63);             // cur2 < D * 2^32
}
```

Если какой-либо из этих `assert` когда-нибудь упадёт, значит, формулы `drop` и экспоненты нужно пересчитать заново.
